手机上部署破甲 —— 完整操作单
================================

========================================================
最快路径：一句话交给 agent（推荐）
========================================================

把下面这段整段发给 DSH Go 里的 agent（确认主机是「本机」）：

请执行这条命令，把完整输出贴回来（就十几行）：

mkdir -p /root/phone-armor && cd /root/phone-armor && \
node -e "fetch('https://raw.githubusercontent.com/zwg1097551433/phone-armor/main/deploy.sh').then(r=>r.text()).then(t=>require('fs').writeFileSync('deploy.sh',t))" && \
sh deploy.sh

它会自己探测环境、装四层、判定结果；失败时自动换方案重试。
成功时最后一行是「部署完成」。

如果它报未完成，再让它跑这两条：

sh deploy.sh --log | tail -30
cd /root/phone-armor && sh armor.sh status

deploy.sh 的自愈逻辑：
  · 自己找 node（PATH → /opt/dsh/bin → /opt/dsh-app/*）
  · 自己找宿主 @deepseek-ai（固定候选 → 通配 → find 兜底）
  · 宿主只读 → 自动切规则层模式（不打源码补丁）
  · 补丁命中偏低 → 自动 repair 一次
  · 全程日志写 deploy.log，屏幕只留结论

只想要规则层、不动宿主源码：

sh deploy.sh --rules

========================================================
以下是完整手动流程（自动模式失败时用）
========================================================


（按 DSH Go 1.1.0 实测环境写：引擎 DSH 0.2.2-rc.1 · Node v24.22.1 · App 路径 /opt/dsh-app/ · 端口 3080）


---------------------------------------------------------------
第 0 步：发送文本之前，先在 App 里做两件事（30 秒）
---------------------------------------------------------------

1. 设置 → 本机引擎 → **关掉「自动进入安全模式」**
   开着的话，破甲一旦让启动失败会被静默跳过，界面看起来一切正常，极难排查。

2. 顺手记住「以安全模式启动（不加载插件）」在哪
   装坏了用它进去卸插件 —— 手机上没有电脑那种恢复 bat。


---------------------------------------------------------------
第 1 步：把下面整段复制给 agent
---------------------------------------------------------------
（先把 OWNER 换成你的 GitHub 用户名、REPO 换成仓库名；在电脑上跑 set-repo.ps1 会自动换好）


你是 DSH Go 的本机引擎，跑在 PRoot Ubuntu 里（DSH 0.2.2-rc.1，node v24）。现在要在这台手机上安装破甲包，仓库地址：

  https://github.com/zwg1097551433/phone-armor

按顺序做完，把每一步的完整输出原文贴回来（不要总结、不要省略）：

第 1 步 —— 下载自举脚本到 /root/phone-armor/bootstrap.sh
  三个源按顺序试，前一个成功就停：
    https://cdn.jsdelivr.net/gh/zwg1097551433/phone-armor@main/bootstrap.sh
    https://raw.githubusercontent.com/zwg1097551433/phone-armor/main/bootstrap.sh
    https://gh-proxy.com/https://raw.githubusercontent.com/zwg1097551433/phone-armor/main/bootstrap.sh
  兜底命令（手机一定有 node）：
    mkdir -p /root/phone-armor && cd /root/phone-armor && \
    node -e "fetch('https://raw.githubusercontent.com/zwg1097551433/phone-armor/main/bootstrap.sh').then(r=>r.text()).then(t=>require('fs').writeFileSync('bootstrap.sh',t))"

第 2 步 —— 执行
    cd /root/phone-armor && sh bootstrap.sh

执行纪律：
  1. 只跑这两步，不要自己改脚本、不要跳过 SHA256 校验、不要手工拼安装命令。
  2. 任何一步报错就立刻停，把报错原文贴回来；不要"换个办法试试"。
  3. 装完不要重启引擎，我自己去 设置 → 本机引擎 → 停止 → 启动。
  4. 报「找不到 DSH_HOME」或「找不到 node」时直接贴输出，不要自己造路径。

我要确认的：最后那段「完成：N 条补丁已清洗」里的 N，以及它上面的整段输出。

---------------------------------------------------------------
第 2 步：等它跑完
---------------------------------------------------------------

成功时最后几行长这样：

  bootstrap 完成。回 App：设置 → 本机引擎 → 停止 → 启动。

    A 破甲本体   已装（补丁数见上方）
    预检         每次发工作指令先做三档评级，二/三档弹窗，你选继续才执行
    命令提示     配置在 /etc/phone-armor/guard.conf：0 只提示 / 1 拦截 / 2 放行

上面还会有一段 `完成：74 条补丁已清洗（marker: ...）`。

然后回 App 停止再启动本机引擎，补丁才加载。

装好之后的效果：发一条工作指令，主 agent 会先停一下，弹出一张风险卡片告诉你
这条活属于第几档、为什么、换哪条路。选「继续执行」它才真的干活。


---------------------------------------------------------------
如果第一条消息就被弹窗拦住
---------------------------------------------------------------

现象：发出去之后弹「环境还没配好 / 需要 Kali」，消息发不出去。

这是 dsh-purge-community 前端 `EnvAdaptSendGate` 的缓存时序 bug —— 手机新开页面缓存是空的，第一次发送必弹。
（判定逻辑只在会话前两步生效，所以老会话不会拦。）

处理：弹窗上点「确认暂不配置」。这会写 `~/.dsh/redteam/config.json` 的 `envAdaptSkip=true`，之后不再弹。
点完再发一次那段文本即可。


---------------------------------------------------------------
如果三个下载源全部失败
---------------------------------------------------------------

GitHub 的 raw / CDN 在某些网络下都不通时，改走「附件上传」这条路（能过网就行）：

  1. 手机浏览器打开 http://127.0.0.1:3080/?token=...   （token 从 App 日志里复制）
  2. 在 DSH Web 界面新建会话，把下面这个文件作为附件上传：
       dsh-purge-community-1.6.91.tgz        （2.1 MB）
       prompt-inject.md                      （25 KB）
  3. 附件会落在 PRoot 内的 ~/.dsh/attachments/ 下
  4. 让 agent 执行：

       find /root/.dsh/attachments -name '*.tgz' 2>/dev/null
       mkdir -p /root/phone-armor/payload
       cp <上一步找到的路径> /root/phone-armor/payload/
       cp <prompt-inject.md 的路径> /root/phone-armor/payload/

  5. 再把 armor.sh、verify.sh 也用同样方式传进去（或让 agent 从仓库拉这两个小文件），然后：

       cd /root/phone-armor && sh armor.sh install

  另一种更可控的做法：手机 Web 界面里有 terminal，直接在那儿跑 `sh bootstrap.sh`，
  能看实时输出，也不占 agent 的上下文。


---------------------------------------------------------------
另一条通道：手机 Web 界面自带 terminal
---------------------------------------------------------------

手机浏览器打开 http://127.0.0.1:3080/?token=...（token 从 App 日志复制），界面里的 terminal
就是 PRoot 里的 shell。想自己动手、看实时输出、或者 agent 那边卡住时，都在这里跑：

    cd /root/phone-armor && sh armor.sh check      # 先体检
    cd /root/phone-armor && sh bootstrap.sh        # 再装


---------------------------------------------------------------
以后重复部署（第二台、第三台手机）
---------------------------------------------------------------

同一段文本原样发过去。脚本是幂等的：已装好自动跳过，坏了自动修。

App 升级引擎之后补丁会被覆盖，同样发这段文本 —— 或者只让它跑：

    cd /root/phone-armor && sh armor.sh repair


---------------------------------------------------------------
出错对照表
---------------------------------------------------------------

  找不到 DSH_HOME          → App 里从没启动过本机引擎，先启动一次再重跑
  找不到 node              → 同上；引擎还没初始化完
  tgz SHA256 不匹配        → 删 /root/phone-armor/payload/*.tgz 重跑
  未定位 @deepseek-ai      → apply 可能只打了一部分；把输出贴回来，用
                             DSH_BASE=/实际路径 指定后重跑 repair
  补丁数明显低于 74        → App 升级导致锚点漂移，贴 --status 输出重新校准
